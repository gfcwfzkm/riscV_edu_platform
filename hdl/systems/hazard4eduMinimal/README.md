# hazard4eduMinimal

Minimal SoC for the GECKO5Education (Lattice ECP5 LFE5U-85, CABGA381): the Hazard3 core with Wishbone
ports (`hazard3_cpu_2port_wb`), JTAG debug, 64 KiB of SRAM and a 16550 compatible UART on the shared Wishbone
bus generated by `hdl/busgenerators/java` from `wishBone.xml`.

| Address                     | Slave       | Notes                                                     |
|-----------------------------|-------------|-----------------------------------------------------------|
| `0x0000_0000 – 0x0000_ffff` | `sramSlave` | 64 KiB block RAM, reset vector and `mtvec` at `0x0`        |
| `0x0001_0000 – 0x0001_0007` | `uartBus`   | 16550 registers (byte access), baud clock 50 MHz          |

Bus masters: the debug module's system bus access (`debugIf`), the CPU load/store port (`cpuData`) and the
CPU instruction fetch port (`cpuInstr`).

CPU configuration: **RV32IM** + Zicsr, M-mode traps, counters, debug with 2 hardware breakpoints, 1 IRQ
line (tied low). The C extension, the A extension and the Xh3irq interrupt controller are off for timing on
a speed grade 6 part: with C the core only reaches about 41-45 MHz, and with A and Xh3irq about 50 MHz,
instead of about 51-54 MHz without them. Build software with
`-march=rv32im -mabi=ilp32`.

The RAM is not initialised by the bitstream: programs are loaded over JTAG.

## Build and load

Tools: Yosys, nextpnr-ecp5, ecppack, openFPGALoader and OpenOCD, e.g. from the
[OSS CAD Suite](https://github.com/YosysHQ/oss-cad-suite-build). The Makefile uses `/opt/oss-cad-suite` when it
exists; set `OSS_CAD_SUITE=...` for another location, or have the tools on `PATH`.

```bash
make              # build/hazard4eduMinimal.bit (synthesis + place & route take about a minute)
make load         # configure the FPGA (SRAM, volatile)
make run ELF=prog.elf   # load a program over JTAG into the SRAM and start it at 0x0
make flash        # write the bitstream to the SPI flash (persistent)
make openocd      # OpenOCD server for gdb (:3333) / telnet (:4444), e.g. for VS Code
make console      # the board's UART in minicom, 115200 8N1 (quit with Ctrl+A X)
```

The board is found by its FT2232H product string (`Dual RS232-HS`), so other FT2232 based probes can stay
connected. Override with `GECKO_BUSDEV=<bus>:<device>` if needed.

## Debugging

JTAG and the UART share the board's FT2232H: channel A is JTAG (FPGA configuration **and** the Hazard3 debug
module, which sits behind the ECP5's own TAP on the ER1/ER2 instructions), and channel B is the UART (the second
`ttyUSB` of the board; the baud rate is set by software, divisor = 50 MHz / (16 × baud), e.g. 27 for
115200). While OpenOCD connects or disconnects, the FTDI chip is
reset, and a few UART characters can be lost.

OpenOCD configuration: `openocd/gecko5-hazard3.cfg`. Use it with gdb (`target extended-remote :3333`) or, for
example, the VS Code Cortex-Debug / native debug extensions with a `riscv32` / `riscv64-unknown-elf` gdb.
